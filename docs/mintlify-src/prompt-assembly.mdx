The conversation prompt sent to the LLM is **assembled at runtime** from multiple pieces. The live app and the simulator assemble them slightly differently.

---

## Live App — Conversation Turn

```
conversation-prompt.md          ← shell template (contains base rules + framing)
    + profile-A0/A1/A2/B1/B2/C1.md   ← injected as {{LEVEL_BLOCK}}
    + unit name, focus          ← from curriculum_data.py
    + target skill IDs + text   ← from due_next in DB
    + elicitation plan          ← generated from curriculum_data.py
    + student memory facts      ← from user.persona_memory in DB
    + current turn number       ← runtime counter
    + conversation history      ← all previous messages
```

**Final system prompt size:** ~800–1200 words depending on level and memory.

---

## Variables Injected at Runtime

| Variable | Source | Example |
|---|---|---|
| `{{LEVEL_BLOCK}}` | `profile-{level}.md` file | "LEVEL: A0. Your role: ECHO-BUILDER..." |
| `{{UNITNAME}}` | curriculum_data.py → active unit | "First words" |
| `{{UNITFOCUS}}` | curriculum_data.py → active unit focus | "Naming the things I can see." |
| `{{TARGETS}}` | user.due_next + curriculum | "- [U1-VOC-01] I can name colours and say numbers" |
| `{{ELICITATION}}` | plan_text() from curriculum_data.py | "Ask: what colour is your bag?" |
| `{{STUDENT_MEMORY}}` | user.persona_memory from DB | "- Likes cricket\n- Lives in Delhi" |
| `{{CURRENT_TURN}}` | turn counter (1–6) | "3" |

## Which Profile Gets Selected?

Based on `user.level` stored in DB:

| User Level | Profile File | Role Name |
|---|---|---|
| A0 | `profile-A0.md` | ECHO-BUILDER |
| A1 | `profile-A1.md` | CARRIER |
| A2 | `profile-A2.md` | BRIDGE-BUILDER |
| B1 | `profile-B1.md` | SPACE-CREATOR |
| B2 | `profile-B2.md` | SPARRING PARTNER |
| C1 | `profile-C1.md` | PEER |

## Placement — NOT Modular

Placement uses a single self-contained file (`placement-check-prompt.md`). No assembly needed because:
- There is no level yet — that's what placement figures out
- No unit/skill targets to inject
- No profile to select
- It's a standalone adaptive interview with its own rules

Only 2 variables: `{{NAME}}` and `{{AGE}}`.

---

## Session Analysis — Post-Session

After a conversation ends, `end-result-prompt.md` is assembled with:

| Variable | Source |
|---|---|
| `{{LEVEL}}` | user.level |
| `{{UNIT_LABEL}}` | current unit name |
| `{{TOPIC}}` | session topic |
| `{{TARGET_SKILLS}}` | skill IDs aimed at this session |
| `{{FULL_TRANSCRIPT}}` | all messages joined |

## Simulator vs Live App

The simulator has **two modes**:

| Mode | How it assembles the prompt |
|---|---|
| **Client (Mock/Local)** | Uses hardcoded blocks in the HTML: `base` + `profileA0/A1/B1` + `convSkill/convUnit`. Offline, no API key needed. |
| **Server (Active Production)** | Fetches real prompt files from `/admin/prompts`. Shows exactly what the live app is running. Read-only. |

The **Client tab** is for fast local experimentation. The **Server tab** is for QA validation — it shows the real production prompts.

<Note>
The simulator's Client mode has 3 profile levels (A0, A1, B1) while the live app has 6 (A0–C1). Use the Server tab when you need to test exactly what production users see.
</Note>

## Where to Edit

| What you want to change | Edit this file |
|---|---|
| Zoe's core personality / absolute rules | `conversation-prompt.md` |
| How Zoe behaves with A0 students | `profile-A0.md` |
| How Zoe behaves with A1 students | `profile-A1.md` |
| How Zoe behaves with B1 students | `profile-B1.md` |
| Post-session analysis logic | `end-result-prompt.md` |
| Placement screening behavior | `placement-check-prompt.md` |
| Correction extraction | `llm_service.py` → `extract_correction_highlight()` |

After editing any `.md` file → redeploy the backend Docker container for changes to take effect.

## Known Issues

<Warning>
**`base-prompt.md` and `conv-unit-framing.md` are duplicated.** Their content is embedded inside `conversation-prompt.md` for the live app. Editing these standalone files only affects the simulator's Client tab — not the live app.
</Warning>

<Warning>
**A0 profile compliance is imperfect.** The rules in `profile-A0.md` are written as instructions, but the LLM drifts toward fluent conversational responses. The simulator's rule checker will flag violations. Fix: add few-shot examples to `profile-A0.md`.
</Warning>
