## 1. Three Problems We Solved

| Problem | What was happening | How we solved it |
|---|---|---|
| **Repetition** | Same skill every conversation (no variety) | **Recency penalty** — after being primary, a skill gets penalized for next 3-4 sessions |
| **Frustration** | Student struggles with one skill, gets stuck forever | **Consecutive zeros** — after 2 fails with no evidence, open the next unit |
| **Rigidity** | Skills practiced in fixed order regardless of performance | **Priority scoring** — 6 weighted factors decide what to practice next |

---

## 2. The Rotation Logic (Recency)

### What it does

After every conversation, the primary target gets a **cooldown penalty**. This forces a different skill to become the next primary target.

### When it matters

When there are **multiple un-owned skills** in the current unit. The recency penalty ensures ELLA cycles through all of them rather than repeating one.

### How it works

```text
Conversation ends
       ↓
Primary target added to "recently practiced" list (max 4)
       ↓
Next time, that skill gets penalty: recent_count / 4.0
       ↓
Other skills now score higher
       ↓
Different skill becomes primary
```

## 3. The Consecutive Zeros Logic (Stuck-Skill)

### What it does

If the same skill has been the primary target **2 times in a row** and the student scored **0 evidence both times** (below 0.70 threshold), ELLA opens the next unit's skills.

### What problem it solves

Imagine: Unit 1 has 4 skills. The student owns 3 of them. Only GRA-01 remains. Without this logic:

```text
Conv 1 → GRA-01 → 0 evidence
Conv 2 → GRA-01 → 0 evidence
Conv 3 → GRA-01 → 0 evidence  ← stuck forever!
Conv 4 → GRA-01 → 0 evidence
...
```

The student is trapped. They can't progress because they keep failing the same skill, and there's nothing else to rotate to.

### With consecutive zeros logic:

```text
Conv 1 → GRA-01 → 0 evidence (consecutive_zeros = 1)
Conv 2 → GRA-01 → 0 evidence (consecutive_zeros = 2) ← TRIGGER!
Conv 3 → U2-VOC-01 → next unit opens! Student makes progress.
Conv 4 → U2-GRA-01 → fresh skills, fresh opportunities
Conv 5 → GRA-01 → comes back for another try (recency decayed)
```

### The trigger rule

```text
IF:
  - ALL remaining skills in the current unit have consecutive_zeros >= 2
  
THEN:
  - Also include skills from the NEXT unit in the candidate pool
  - Run priority scoring on the combined pool
  - Fresh next-unit skills naturally win (high Uncertainty + zero Recency)
  - Stuck skill stays in pool but ranked low — comes back later
```

### When does consecutive_zeros reset?

- **Resets to 0** as soon as the skill gets ANY qualifying evidence (confidence >= 0.70)
- So if the student finally demonstrates the skill, it leaves the "stuck" state immediately

## 4. What Happens to the Stuck Skill? (Spaced Retries)

When the next unit opens, the stuck skill (e.g. U1-GRA-01) does NOT disappear. It stays in the candidate pool alongside Unit 2 skills. Every session, ALL candidates are scored and the highest wins.

### Why Unit 2 skills win initially (numerical example):

After the trigger fires, here's what the priority scoring looks like:

| Skill | Need (35%) | Uncertainty (20%) | ReviewDue (20%) | Curriculum (15%) | Variety (10%) | Recency (-25%) | **TOTAL** |
|---|---|---|---|---|---|---|---|
| **U2-VOC-01** | 0.35 (mastery=0) | 0.20 (never seen) | 0.20 (never practiced) | 0.12 | 0.10 (never) | 0.00 (not recent) | **0.97** |
| **U2-GRA-01** | 0.35 | 0.20 | 0.20 | 0.10 | 0.10 | 0.00 | **0.95** |
| **U1-GRA-01** | 0.35 (mastery=0) | 0.14 (seen 2x) | 0.05 (just yesterday) | 0.15 | 0.05 (seen 2x) | -0.06 (recent) | **0.68** |

U1-GRA-01 loses because:
- Low Uncertainty (already seen it 2 times)
- Low ReviewDue (just practiced yesterday)
- Low Variety (practiced before)
- Has Recency penalty (was primary recently)

Unit 2 skills have perfect scores (everything is fresh/new).

### After 4 sessions of Unit 2 practice:

| Skill | Need | Uncertainty | ReviewDue | Curriculum | Variety | Recency | **TOTAL** |
|---|---|---|---|---|---|---|---|
| **U1-GRA-01** | 0.35 (mastery still 0) | 0.14 | 0.18 (4 days passed!) | 0.15 | 0.05 | 0.00 (not recent anymore) | **0.87** |
| **U2-VOC-01** | 0.24 (mastery=0.32) | 0.14 (seen 1x) | 0.05 (just practiced) | 0.12 | 0.05 | -0.06 (recent) | **0.54** |

Now U1-GRA-01 WINS because:
- Its ReviewDue increased (hasn't been practiced in 4 days)
- Its Recency penalty is gone (wasn't primary recently)
- Unit 2 skills now have their own recency penalties

### The cycle repeats:

```text
Sessions 15-18: Unit 2 skills rotate (GRA-01 in pool but loses)
Session 19:     GRA-01 rises back → becomes primary → gets another try
                   ↓
           Student succeeds? → Evidence! → cz resets → eventually owned
           Student fails?    → Back to pool → tries again in 4-5 sessions
```

### Key point:

The stuck skill comes back every **4-5 sessions** because:
1. Recency decays after 3-4 sessions
2. ReviewDue keeps growing (spaced repetition effect)
3. Need stays high (mastery is still near 0)

This creates **natural spaced retries** — the student gets periodic chances to demonstrate the skill without being trapped on it.

| 4 | **U2-GRA-01** | 0.70 | ✅ | 0.28 | U2-VOC-01 recency → next fresh skill |
| 5 | **U2-GRA-02** | 0.75 | ✅ | 0.30 | U2-GRA-01 recency → next fresh skill |
| 6 | **U2-FLU-01** | 0.80 | ✅ | 0.32 | U2-GRA-02 recency → last fresh skill |

│  │   (Recency)  │  │   (Stuck Detection)  │    │
│  │              │  │                      │    │
│  │ "Don't       │  │ "If failing the      │    │
│  │  repeat the  │  │  same skill 2x in    │    │
│  │  same skill  │  │  a row, open next    │    │
│  │  next time"  │  │  unit"               │    │

│         └──────────┬───────────┘                │

## 7. Testing Checklist

### For Scenario A (student getting evidence):

- [ ] Primary target changes after every conversation
- [ ] No skill repeats as primary 3+ times in a row
- [ ] All 4 unit skills appear as primary within 10 conversations
- [ ] Garden grows (sightings increase each session)
- [ ] Skills with higher mastery get selected less often

### For Scenario B (student stuck):

- [ ] After 2 zero-evidence sessions on same skill, primary changes to a different unit's skill
- [ ] The stuck skill still comes back every 3-4 conversations for a retry
- [ ] When the stuck skill finally gets evidence, consecutive_zeros resets
- [ ] Student makes visible progress on the new unit's skills
- [ ] Garden still grows on the new skills

### How to verify in Admin:

1. **Admin → Sessions → View** for each conversation
2. Look at **"Conversation Prompt Used"** → check `Primary target:`
3. Confirm it changes between sessions
4. After 2 zeros: confirm the next primary is from the **next unit** (U2-xxx instead of U1-xxx)
5. **Admin → Memory** → check `due_next` field shows the new targets

## 8. Summary

| Logic | Trigger | Effect |
|---|---|---|
| **Recency** | Skill was just primary | Gets penalized for 3-4 sessions |
| **Consecutive Zeros** | Same skill, 2x zero evidence in a row | Opens next unit's skills |
| **Priority Scoring** | Always runs | Picks the highest-value skill to practice next |

> **In one sentence:** "ELLA rotates skills using recency, moves forward when stuck using consecutive zeros, and always picks the most valuable next skill using priority scoring."
